📚 Resumo — Elicitação de Requisitos — Aula 3
1. Requisito Funcional (RF)

É o que o sistema deve fazer.

Exemplos:

Cliente adiciona produto ao carrinho.
Restaurante aceita ou recusa um pedido.
Cliente acompanha o pedido no mapa.
2. Requisito Não Funcional (RNF)

É como o sistema deve se comportar, envolvendo qualidade, desempenho ou restrições.
Exemplos:

Checkout responder em até 2 segundos.
Login exigir autenticação em dois fatores.
Sistema ter 99,9% de disponibilidade.

👉 Resumindo:
RF = o que faz.
RNF = como deve fazer.

3. ISO/IEC 25010

É uma norma que padroniza características de qualidade de software.

As 8 características são:

Adequação funcional — atende às necessidades?
Eficiência de desempenho — é rápido e usa bem os recursos?
Compatibilidade — funciona com outros sistemas?
Usabilidade — é fácil de aprender e usar?
Confiabilidade — continua funcionando e se recupera de falhas?
Segurança — protege os dados?
Manutenibilidade — é fácil modificar/corrigir?
Portabilidade — é fácil levar para outro ambiente?

4. Um bom RNF precisa ser:
Testável e mensurável
Não ambíguo
Atômico e completo
Viável

Por exemplo:

❌ "O sistema deve carregar rapidamente."
✅ "Os dados devem carregar em até 1,5 segundo em 95% das chamadas."

A ideia é transformar termos vagos como rápido, seguro e eficiente em algo que possa ser medido e testado.

5. Triângulo de Ferro
Os três elementos são:
Escopo ↔ Tempo ↔ Custo
Se você mexe em um, normalmente precisa mexer em outro para manter a qualidade.

Exemplo:

Quer mais funcionalidades?
Mantendo o mesmo prazo?
Provavelmente precisará de mais custo/equipe.

Não existe, na prática, fazer algo mais rápido + mais barato + mais completo ao mesmo tempo.

6. Negociação de escopo

Quando dois requisitos entram em conflito, é necessário decidir o que realmente precisa entrar no produto.
O PO (Product Owner) ajuda nessa decisão, buscando um MVP real: o menor conjunto de requisitos que ainda entrega valor.
Exemplo da aula: o login social poderia ficar para uma atualização posterior para não comprometer a data de lançamento.




📝 Questionário — bem resumido

1. O que é um requisito funcional?
➡️ É aquilo que o sistema deve fazer.

2. O que é um requisito não funcional?
➡️ Define como o sistema deve se comportar, incluindo qualidade e restrições.

3. Qual a principal diferença entre RF e RNF?
➡️ RF = o que faz. RNF = como faz.

4. Para que serve a ISO/IEC 25010?
➡️ Para padronizar e avaliar a qualidade do software.

5. Cite 4 características da ISO 25010.
➡️ Usabilidade, segurança, confiabilidade e portabilidade.
(Existem 8 no total.)

6. Como deve ser um bom RNF?
➡️ Testável, mensurável, não ambíguo, completo e viável.

7. Por que "o sistema deve ser rápido" é um RNF ruim?
➡️ Porque "rápido" é subjetivo e não é mensurável.

8. O que representa o Triângulo de Ferro?
➡️ Escopo, tempo e custo.

9. O que acontece quando aumentamos o escopo mantendo o prazo?
➡️ Pode ser necessário aumentar o custo/equipe ou retirar outra parte do escopo.

10. O que é um MVP?
➡️ O menor conjunto de requisitos que ainda entrega valor real ao usuário.

RNF = como ele deve fazer.
ISO 25010 = qualidade.
RNF bom = mensurável e testável.
Triângulo = escopo + tempo + custo.
MVP = mínimo que já entrega valor.
