# 📚 Resumo — Elicitação de Requisitos — Aula 4

## 1. Levantamento de Requisitos

→ É descobrir e coletar as **necessidades reais** do sistema.
→ É um processo **contínuo**, não acontece só uma vez.
→ **Requisito implícito** = necessidade que ninguém documentou porque parecia óbvia.

## 2. Fontes de informação

Existem **2 tipos**:

**Humanas** → Pessoas
→ Cliente, usuário, gerente, PO etc.

**Não humanas** → Registros
→ Documentos, sistema legado, concorrentes e normas.

👉 **Humana = contexto e motivo.**
👉 **Não humana = volume e precisão.**

## 3. Stakeholder

→ Pessoa ou grupo que possui **interesse ou influência** sobre o sistema.

**3 níveis:**

→ **Estratégico** = define objetivos.
→ **Tático** = transforma/prioriza requisitos.
→ **Operacional** = utiliza o sistema.

⚠️ Usuários diferentes podem ter necessidades diferentes, então devem ser separados por **classe de usuário**.

## 4. Fontes não humanas

**Documentação** → o que já foi escrito.
**Sistema legado** → o que já funciona.
**Concorrência** → o que o mercado espera.
**Normas** → o que é obrigatório.

⚠️ Não copiar cegamente documentos, sistemas ou concorrentes.

## 5. Roteiro do levantamento

→ Documentação
→ Sistema legado
→ Concorrência
→ Normas
→ Stakeholders
→ Confirmar o que ainda estiver incerto.

# 📝 Questionário — bem resumido

**1. O que é levantamento de requisitos?**
➡️ Descobrir as necessidades reais do sistema.

**2. Quais são as duas fontes de informação?**
➡️ Humanas e não humanas.

**3. Cite 4 fontes não humanas.**
➡️ Documentação, sistema legado, concorrência e normas.

**4. O que é um stakeholder?**
➡️ Pessoa ou grupo com interesse ou influência no sistema.

**5. Quais os 3 níveis de stakeholder?**
➡️ Estratégico, tático e operacional.

**6. O que é requisito implícito?**
➡️ Uma necessidade que não foi documentada por parecer óbvia.

**7. Por que separar classes de usuários?**
➡️ Porque cada usuário pode ter necessidades e acessos diferentes.
